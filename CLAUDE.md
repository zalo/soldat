## Project Overview

OpenSoldat is a 2D side-view multiplayer action game written in FreePascal (Object Pascal, Delphi-compatible mode). This is the open-source 1.8 version. The codebase has three main components: game client, dedicated server, and shared code.

## Build Commands

### Linux (Ubuntu)
```bash
# Install dependencies (first time)
sudo apt-get install build-essential g++ cmake git fpc libprotobuf-dev protobuf-compiler libssl-dev libsdl2-dev libopenal-dev libphysfs-dev libfreetype6

# Build (from repo root)
mkdir build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Debug
make

# Build server only
cmake .. -DBUILD_CLIENT=0
make

# Build client only
cmake .. -DBUILD_SERVER=0
make

# Release build with assets
cmake .. -DCMAKE_BUILD_TYPE=Release -DADD_ASSETS=1
make
```

### Running
```bash
# Start server first, then client
./build/bin/soldatserver
./build/bin/soldat -join 127.0.0.1 23073
```

### CMake Options
- `BUILD_CLIENT` / `BUILD_SERVER` - toggle which to build (default: both True)
- `ADD_ASSETS` - download soldat.smod and font (default: True)
- `BUILD_GNS` - build GameNetworkingSockets library (default: True)
- `BUILD_STEAM` - Steam integration (default: False)
- `ADD_BFT` - copy BFT integration tests to scripts dir (default: False)
- `ADD_FFI_FUZZ` - enable ScriptCore FFI fuzz tests (default: False)
- `CROSS_LINUX_64`, `CROSS_WINDOWS_64`, etc. - cross-compilation targets

### Tests
Server ScriptCore tests are in `server/scriptcore/test/`:
- **BFT tests**: integration tests for ScriptCore3 game logic (`test/bft/`), enabled with `-DADD_BFT=1`
- **FFI fuzz tests**: tests for FFI assembly (`test/ffi/`), generated by `gen_ffi_tests.py`, enabled with `-DADD_FFI_FUZZ=1 -DBUILD_SCRIPTCORE=1`

## Architecture

### Three-Component Structure
- **`client/`** - Game client: rendering (OpenGL via dglOpenGL), input (SDL2), audio (OpenAL), UI. Entry point: `soldat.lpr` → `Client.pas`
- **`server/`** - Dedicated server: game loop, player management, scripting engine, RCON. Entry point: `soldatserver.lpr` → `Main.pas`
- **`shared/`** - Code shared between client and server

### Shared Code (`shared/`)
- **`mechanics/`** - Core gameplay physics: `Sprites.pas` (player movement/animation), `Bullets.pas` (ballistics), `Control.pas` (player controls), `Things.pas` (pickups/objects), `Sparks.pas` (particles)
- **`network/`** - Network protocol: `Net.pas` (core), `NetworkClient*.pas` / `NetworkServer*.pas` (client/server-specific networking for bullets, sprites, connections, etc.)
- **`libs/`** - Library bindings: GameNetworkingSockets (Valve's networking), PhysFS (filesystem), SteamWrapper, KrakenSDK
- **`Cvar.pas`** - Console variable system for configuration
- **`Game.pas`** - Game state and rules
- **`Constants.pas`** - Game constants

### Server Scripting (`server/scriptcore/`)
PascalScript-based scripting engine (~14k lines) for server-side game customization. Provides API adapters for players, teams, weapons, maps, and an event dispatcher system. The scripting core lives in `ScriptCore3.pas` with game-specific APIs in `ScriptGame.pas`, `ScriptPlayer.pas`, etc.

### Third-Party Code (`3rdparty/`)
- `pascalscript/` - PascalScript implementation (server scripting engine)
- `Pascal-SDL-2-Headers/` - SDL2 Pascal bindings

## Language and Compiler

- **FreePascal 3.0.4+** with Delphi-compatible mode (`-MDelphi`)
- Compiler flags: `-Scgi` (classes, goto, inline), `-B` (build all units)
- Debug builds define `DEVELOPMENT`; release builds define `TESTING`
- Platform-conditional compilation uses `{$IFDEF MSWINDOWS}`, `{$IFDEF UNIX}`, `{$IFDEF DARWIN}`, etc.
- PascalCase for types/units, camelCase for local variables

## Key Dependencies

- SDL 2.0.12+ (graphics/input), OpenAL (audio), FreeType 2.6.1+ (fonts)
- PhysFS 3.0.2 (virtual filesystem for game assets)
- GameNetworkingSockets v1.4.0 (Valve's reliable UDP networking)
- OpenSSL, ProtoBuf (required by GNS)

## Web Port (`feature/web-port` branch)

An in-progress port of OpenSoldat to the web browser using FPC's wasm32 target + a JS bridge layer. See the design spec and implementation plan for full context:
- **Design spec**: `docs/superpowers/specs/2026-04-05-web-port-design.md`
- **Implementation plan**: `docs/superpowers/plans/2026-04-05-web-port.md`

### Building the web port

Requires FPC trunk 3.3.1 with wasm32-wasip1 target (installed at `~/fpc-trunk/`). See `~/.claude/projects/-home-selstad-Desktop-soldat/memory/reference_fpc_wasm_setup.md` for setup details.

```bash
# Build both client and server WASM
cd web && bash build.sh all

# Run locally
python3 -m http.server 4000 --bind 127.0.0.1   # in web/ directory
# Open http://localhost:4000/shell.html

# Standalone render test (no assets needed)
# Open http://localhost:4000/test/render-test.html
```

The smod asset file (`web/soldat.smod`, ~105MB, gitignored) must be present. Download from https://github.com/opensoldat/base/releases/download/v0.4/soldat.smod and place in `web/`.

### Architecture

- **Pascal source**: `{$IFDEF WEB}` blocks in ~12 files redirect C library calls (`SDL2`, `OpenGL`, `OpenAL`, `PhysFS`, `GNS`) to WASM imports from the `env` module
- **Web stubs** (`web/stubs/`): replacement units for SDL2, dglOpenGL, OpenAL, SyncObjs, Sockets, BaseUnix, cthreads, fphttpclient, fphttpserver — provide types/constants without native library dependencies
- **JS bridge** (`web/bridge.js`): 60+ WebGL2 functions with handle translation, GLSL 1.20→ES 3.00 auto-conversion, PhysFS replacement (fflate+Map), Web Audio bridge
- **Asset loading** (`web/assets.js`): downloads smod, unzips with fflate, pre-decodes all images via `createImageBitmap` + `OffscreenCanvas`, caches raw smod in IndexedDB
- **STB image bridge** (`web/main.js`): `stbi_xload_mem` matches WASM memory content to pre-decoded images via content hash lookup (file length + first 16 bytes)
- **Game loop**: `web_init` (called from `_start` main block) runs `StartGame`; `web_tick` (called from JS `requestAnimationFrame`) runs `GameInput` + `GameLoop`
- **PartyKit server** (`web/partykit/`): loads `soldatserver.wasm`, routes WebSocket messages to WASM game tick

**Testing with Playwright**: The Playwright MCP plugin is available for automated browser testing. Use `browser_navigate` to `http://localhost:4000/shell.html`, `browser_console_messages` to read logs, and `browser_take_screenshot` to see the canvas. Start the HTTP server first: `cd web && python3 -m http.server 4000`. The smod download takes ~60-90s on first load (cached in IndexedDB after).

**Debugging approach**: The base Pascal code is known-good from native builds. Any bug is in the web interface layer (`{$IFDEF WEB}` blocks, JS bridge, web stubs). A useful technique: add sentinel WriteLn values in key functions and compare the native vs web output to spot where they diverge.

### Key bugs found and fixed during development

- **`stbi_xload_mem` frame count**: the 5th parameter (`fPtr`) is `FNumFrames` (animation frame count), NOT component count. Setting it to 4 caused `Premultiply` to iterate 4x the pixel data → OOB crash
- **`stbi_image_free` heap corruption**: pixel data allocated by JS bump allocator was freed via `FreeMem`, corrupting the FPC heap. Fixed by making `stbi_image_free` a no-op
- **`wasiAlloc` overlap**: FPC's `wasiAlloc` is a simple bump allocator that returns overlapping memory regions. Fixed by using a separate JS bump allocator for image pixel data
- **Unit finalization destroying game state**: FPC's `_start` ends with implicit `Halt(0)` which runs unit finalization sections BEFORE `proc_exit`, destroying all global objects (spritesheets, textures, map data). The old `proc_exit` throw fix was too late. Fixed by calling `web_stop()` (a JS import that throws) from the main block right after `StartGame` returns, aborting before finalization runs
- **`LoadFonts` calling `ShutDown`/`Halt(0)`**: `GetFontPath` uses `FileExists` which doesn't work on WASM. Fixed by making `GetFontPath` return the filename directly on web (JS bridge handles font loading)
- **Font rendering via Canvas 2D**: Created `web/stubs/freetype.pas` that routes FT_* functions to `external 'env'` → JS bridge. The JS `ftBridge` allocates FT_FaceRec/FT_GlyphSlotRec in WASM memory and rasterizes glyphs via OffscreenCanvas. Glyph bitmaps are written to WASM memory for the existing texture atlas packing code
- **GL_LUMINANCE_ALPHA → GL_RG8**: WebGL2 doesn't support GL_LUMINANCE_ALPHA. Mapped to GL_RG8/GL_RG in bridge.js. Added `sampleTex()` GLSL swizzle function to remap `vec4(R,G,0,1)` → `vec4(R,R,R,G)` matching expected `vec4(L,L,L,A)` behavior
- **glTexSubImage2D missing**: Was falling through to the no-op Proxy stub. Added explicit implementation in bridge.js with format remapping
- **`Floor(NaN)` WASM trap**: `BigConsole.CountMax` calculation divides by `FontStyleSize(FONT_SMALL)` which is 0 when fonts aren't loaded → NaN → `Floor` traps on wasm32. Fixed by guarding the division
- **No map loaded**: Web build had no mechanism to load a map. Added `WebLoadDefaultMap` in `Client.pas` to load Arena map at end of `StartGame`
- **Missing `GfxBegin/GfxEnd`**: The web fallback rendering path (when `mg.VertexBuffer = nil`) called `RenderInterface` without `GfxBegin()/GfxEnd()`, so no geometry was flushed. Fixed by wrapping in `GfxBegin/GfxEnd`
- **GL error poisoning draw calls**: Invalid GL calls (glHint, glDisable with unsupported enums) generate errors that accumulate and cause subsequent valid draws to silently fail. Fixed by: (1) filtering invalid glHint/glDisable/glEnable in bridge.js, (2) adding `GfxFlushErrors()` (calls real `glGetError` bridge) before polygon draws, (3) adding `glGetError` to bridge.js (was falling through to no-op Proxy returning 0)
- **GfxEnd overwrites MVP transform**: `GfxEnd()` (batched text rendering) calls `GfxDraw` which leaves the shader's MVP uniform set to the interface ortho matrix. Map polygon draws after `GfxEnd` need to re-set the world transform. Fixed by adding `GfxTransform(GfxMat3Ortho(...))` before Polys[1] and Edges[1] draws on web
- **Camera reset by UpdateFrame**: `UpdateFrame` resets CameraX/Y to near (0,0) every tick via spectator camera logic when `MySprite=0`. The camera position set in `WebLoadDefaultMap` was immediately overwritten. Fixed by forcing camera to (400,350) each tick in `web_tick` when `MySprite=0`
- **FPC Variant `call_indirect`**: Variant type operators use indirect calls that crash on wasm32. Fixed by removing `-dDEVELOPMENT` (which gated the Variant-using `DumpCvar` calls)
- **Frame timing**: `SDL_GetPerformanceCounter/Frequency` stubs returned 0, causing `GameLoop` to never advance time. Fixed by implementing via `performance.now()`
- **File not found**: `Sha1File`, `CreateDirIfMissing`, `WriteLogFile`, `PHYSFS_CopyFileFromArchive` all use the native filesystem which doesn't exist in WASM. Wrapped in `{$IFNDEF WEB}`
